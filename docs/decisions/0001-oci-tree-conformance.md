# ADR 0001 conformance vectors: OCI tree identity

These vectors define externally observable outcomes for implementations of [ADR 0001](0001-oci-tree-object-model.md). `M` denotes one configured mount: prefix `/packages`, registry `https://registry.example:5000`, repository `team/packages`, root tag `oci-auto-http-tree-v1`. `R0`, `R1`, etc. are root-index digests, `D*` directory-index digests, `F*` file-manifest digests, and `B*` layer-blob digests; they stand for actual SHA-256 digests in a test. Index child descriptors below use the ADR's `entry-name` annotation. A test MUST inspect both the public tree behavior and the OCI objects reachable from the root tag; it MUST NOT expect names to appear as OCI tags. These vectors assert typed storage/configuration outcomes and side effects, not HTTP status codes or CLI wording; those mappings belong to the corresponding interfaces' contracts.

| ID | Initial state / action | Expected visible tree | Expected OCI identity / result |
| --- | --- | --- | --- |
| NEST-1 | Start with `M` rooted at an empty leaf `R0`. Write bytes `hello\n` to `/packages/org/tool/1.2/README`. | `/packages/org/` and `/packages/org/tool/` and `/packages/org/tool/1.2/` exist; `/packages/org/tool/1.2/README` returns exactly `hello\n`. | `M`'s root tag resolves to new root `R1`. Its index tree contains `org` → `tool` → `1.2` → `README`. The `README` descriptor names a file manifest `F1` with one layer blob `B1`; `B1` is SHA-256 of the exact six bytes. No tag named for any path component is created. |
| NAME-1 | Write bytes `x` to `/packages/org/a%25b/%2Bmeta%3Fbranch%3Dmain%23sha`. | The stored path is exactly `org/a%b/+meta?branch=main#sha`; `+` is literal plus, not space. The canonical generated link is `/packages/org/a%25b/%2Bmeta%3Fbranch%3Dmain%23sha`. | Root tag remains the configured root tag in `team/packages`. The relevant descriptors carry exact UTF-8 names `a%b` and `+meta?branch=main#sha`; there is no path-derived tag or repository. The file manifest points to the blob for byte `x`. |
| NAME-2 | Request `/packages/a%2Fb`, `/packages/%2e%2e/secret`, `/packages/a//b`, `/packages/%`, or a path component containing an encoded backslash. | Each operation returns `InvalidPath`; no HTTP status is asserted by this storage contract. | Root tag and reachable tree remain unchanged; no registry host, repository, or tag is derived from the rejected text. |
| LIMIT-1 | Write to a single component of exactly 255 UTF-8 bytes, then try one of 256 bytes; separately try a relative path over 4096 UTF-8 bytes or deeper than 128 components. | The 255-byte component is representable. Each over-limit path returns `InvalidPath` without truncation. | The valid name is stored as the exact descriptor annotation under `M`'s tree. Rejected names do not create a manifest, descriptor, or altered root. |
| PAGE-1 | Create 129 one-byte files named `f000` through `f128` as immediate children of `/packages/items`. Then delete `f000` and create `f129`; finally delete `f001` through `f128`, leaving only `f129`. | Listing `/packages/items` returns each present name exactly once in unsigned UTF-8 byte order at each stage; lookups return the correct bytes. | The `items` directory is represented by a branch and at least two leaf pages after insertion. Every node has at most 128 descriptors and is at most 1 MiB; branch ranges exactly equal their subtree first/last names, are ordered/disjoint, and resolve every listed child. Boundary edits update ranges. With only `f129` left, empty pages are removed and any one-child branch is collapsed to a leaf; no deleted name remains. |
| EMPTY-1 | From an empty root, explicitly create the empty directory with storage path `cache` (its configured mount is `/packages`). | Listing the immediate children of the root shows exactly one directory named `cache`; listing `cache` returns zero children. HTTP slash redirects/statuses are outside this vector. | The root descriptor for `cache` has `entry-name=cache` and points to an empty `directory-leaf` index `D0`. It is not represented by a fake file, an empty content blob, or a repository. |
| REPLACE-1 | Write bytes `old` to `/packages/tool.bin`, then replace them with bytes `new`, then write `new` once more. | There is exactly one `/packages/tool.bin`; its returned bytes are `new` after the second and third writes. The first replacement is never partially visible. | After replacement, the root tag points to a tree whose sole `tool.bin` entry references a file manifest/layer for `new`, not `old`. Repeating the identical write is a no-op: root digest is unchanged and exactly one entry remains. The old blob may remain unreachable until registry garbage collection. |
| CONCUR-1 | On one writable service instance rooted at `R0`, synchronize two clients to write distinct paths `/packages/a`=`A` and `/packages/b`=`B` concurrently. | Both operations succeed in some serialized order. Every observed root is a complete tree; after both return, both paths exist with exact bytes. | Each root tag publication names a complete root. The final root contains both entries; neither successful update is lost. If the target's exclusive writer lock cannot be acquired, a write waits or fails explicitly before commit; it MUST NOT proceed unsynchronized. |
| PAGE-LIST-1 | At root `R0`, give directory `list` children `a`, `b`, `c`, `d`; request a page of two entries and retain its token. Publish a new root `R1` that removes `c` and adds `e`, while retaining `R0` by digest. Continue using the token. | First page is `a,b`; continuation is `c,d` from `R0`, with no duplicates and no `e`. A token used for another directory or modified token returns `InvalidCursor`. If the pinned root/page is then made unavailable, continuation returns `StaleCursor` (not an empty page or a page from `R1`). | Both pages use descriptors under the same pinned `R0`; continuation never resolves the current root tag in place of `R0`. Typed errors are distinct as specified in ADR §5. |
| AMBIG-1 | With `R0` current and an exclusive writer lock held, inject a lost response for root-tag publication of intended `R1`: once after the registry commits the tag, once before it does, and once with an unexpected third digest or unreadable tag. | After-commit case resolves to success because the tag reads `R1`. Before-commit case safely retries while still holding the lock and resolves to success only after `R1` is visible. Unexpected/unreadable cases return the distinct `CommitOutcomeUnknown` result and are not retried as a fresh mutation. | `R1` contains a complete new tree; each observation is either `R0` or `R1` except the injected unexpected-third-digest case. Uploaded objects without publication do not become visible. |
| CRASH-1 | Use a fault-injection registry to terminate the process after the root-tag PUT is committed but before its response is received; restart with no local durable intent record. Repeat with termination before root-tag commit. | After restart, serve whichever complete tree the root tag currently names. Do not replay or roll back the interrupted request. The interrupted caller's result is `CommitOutcomeUnknown` unless the caller independently confirms the resulting path state. | Post-commit case has `R1` current; pre-commit case has `R0` current. No new local durable database or hidden intent state is required; unreachable uploads are not visible. |
| REG-1 | Configure registry `https://registry.example:5000`, repository `team/packages`, root tag `oci-auto-http-tree-v1`; attempt invalid repository `Team/Packages` and invalid tag `bad:tag`. | The valid target can be mounted. Invalid repository/tag configuration returns `InvalidMountTarget` before the listener accepts requests; no exact diagnostic wording is asserted here. | All reads/writes use the configured registry, repository, and root tag. Path strings, including `Team/Packages` or `bad:tag`, never override those fields. Repository and tag validity follows the OCI Distribution naming grammar; a custom root tag must also be a valid OCI tag. |
| ALIAS-1 | Configure `/packages` and `/mirror` with the same `(registry endpoint, repository, root tag)` tuple. Write `/packages/readme`; read `/mirror/readme`. | `/mirror/readme` returns the same bytes; the mounts are aliases, not separate copies. | Both prefixes resolve through `team/packages:oci-auto-http-tree-v1` to the same root and child digests. Two different root tags in the same repository, by contrast, identify independent trees. |
| CORRUPT-1 | Seed the configured root tag with an otherwise valid OCI index whose leaf has two descriptors with the same `entry-name=dup`. Attempt both lookup and listing through that reachable leaf. | Both operations return `IntegrityError`; the service does not pick either descriptor, invent a result, or repair the tree. | The root tag and malformed reachable manifest remain unchanged. The duplicate is rejected as an application-tree integrity violation even though the OCI JSON/index is structurally valid. |
| CORRUPT-2 | In separate fixtures, seed a reachable branch with a range that disagrees with its child; a leaf/branch with unsupported `format-version=2`; a child descriptor whose node kind/media type is wrong; and a descriptor with a valid SHA-256 syntax but a missing target manifest/blob. Read/list the affected path. | Every fixture returns `IntegrityError`; no path is guessed, no missing object is silently skipped, and no repair is attempted. | Each root and injected manifest remains unchanged. These fixtures are valid OCI JSON where possible but violate the ADR's tree-level schema or refer to unavailable digest content. Cryptographic self-cycles are not generated because a valid SHA-256-addressed manifest graph cannot be made cyclic without a hash fixed point; readers still maintain cycle detection defensively. |

## Black-box assertions

For every successful mutation, resolve the configured root tag after completion and walk descriptors by digest. Verify every descriptor's digest and size, the one-layer file format, exact path names, and absence of duplicate siblings. For a rejected path, cursor, mount target, or corrupt tree, verify the corresponding typed result and no root change. For concurrent writes, record every root observed by readers and verify each is internally valid; an observation may be the old or new snapshot but never a mixture. PAGE-1 and PAGE-LIST-1 require enough entries and controlled root retention/removal to exercise physical pages and stale cursors. CORRUPT-1 and CORRUPT-2 require seeding valid OCI manifests that violate the tree-level schema or reference missing digest targets. AMBIG-1 and CRASH-1 require a fault-injection registry/proxy that can fail before or after manifest-tag commit. Run registry behavior checks against a real OCI Distribution-compatible registry, not a mock that implements tag publication or blob verification differently.
